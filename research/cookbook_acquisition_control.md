# Post-outcome cookbook acquisition control

Frozen before this diagnostic executes, after reviewing the completed cookbook
answers. This is an evaluator-authored interface control, not a preregistered
model experiment or a novel pagination algorithm.

Target: cookbook task 015, all six original/reminder and Qwen checkpoint arms.
All six recorded trajectories reach a successful filter selecting the recipe
with maximal cooking time and later give an incorrect ingredient list. Replay
each worker's warmup and all fifteen earlier episodes through the unchanged
native MCP server. Require byte-equivalent canonical JSON content and error
flags, target initial preview, and ordered target tool schemas. Stop the target
prefix immediately after its first successful `Recipe_cook_min == 900` filter.
The predicate is chosen after observing this example; no inference of autonomous
query interpretation follows.

From that observed handle, sort ascending by `Ingredient_name`, read the first
three visible values, then repeatedly filter the sorted handle to values greater
than the last visible value. Read each resulting preview and stop when its record
count is at most its preview length. Preserve the complete call/result log. Use
only the remaining portion of the original twenty-call budget. Reject malformed,
unsorted or nonprogressing observations; do not silently claim completeness when
the budget is exhausted. Restrict this diagnostic to a non-null string column
with consistent sort/filter order, a stable table and truthful row counts. These
are explicit source/fixture assumptions, not properties certified by the preview.
Distinct-value enumeration may skip duplicate rows but must not skip distinct
values under these assumptions. This does not recover row multiplicity.

The controller receives only a public handle, column name, budget and tool
responses. It never reads SQLite, reference cards or recorded final answers.
After it returns, a separate evaluator compares its values with the frozen SQL
card and with read-only execution of that SQL against the pinned database.
Report all six results, target-prefix and added calls, and whether the twenty-call
budget suffices. Six matched histories of one question are not six independent
tasks. No model continuation, repaired model success rate, general null handling,
universal interface completeness or publication-ready contribution is claimed.
